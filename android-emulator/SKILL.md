# Android 模拟器

在本机 Linux 桌面完成“选择虚拟设备 → 启动系统 → 安装应用 → 显示与操作 → 验证”的闭环。只执行当前请求涉及的步骤；询问原理或查看状态不代表授权启动、安装或重启设备。使用中文，报告真实结果。

## 先分清几个对象

- **AVD（Android Virtual Device，安卓虚拟设备配置）**：由 Android SDK 工具或 Android Studio 创建，保存系统镜像、架构、内存和数据盘配置；它是可启动的配置，不是已经运行的设备。
- **Emulator（安卓模拟器）**：SDK 提供的程序，加载 AVD 并实际运行 Android 和 APK。`-no-window` 只隐藏自带窗口，系统仍在运行。
- **ADB（Android Debug Bridge，安卓调试连接工具）**：SDK 提供的命令行工具，负责识别运行设备、安装应用和执行设备命令。它识别的设备序号与 AVD 名称不同，每次启动可能变化。
- **scrcpy**：将已连接设备的画面显示为本机窗口并转发鼠标和键盘输入；它不创建或替代模拟器。关闭 scrcpy 窗口不会自动关闭模拟器。

首次介绍这些概念时说明职责，不将“打开镜像窗口”“启动 Android 系统”和“启动应用”混为一步。

## 发现并复用

1. 检查项目 `AGENTS.md`、APK/构建模块、最低系统版本、CPU 架构和网页组件要求。先做独立的只读检查，缺少不影响当前步骤的信息不必阻塞。
2. 定位 SDK：优先使用任务指定位置，再检查 `ANDROID_HOME` / `ANDROID_SDK_ROOT`、项目 `local.properties` 的 `sdk.dir` 和本机现有路径。不要改写这些配置来迁就示例。
3. 运行该 SDK 的 `emulator -list-avds` 和 `adb devices -l`。对候选 `emulator-*` 使用 `adb -s <serial> emu avd name` 对应配置名称；结合 API、架构和任务选择目标。
4. 优先复用符合要求的运行实例。只有实体手机时，不自动将其作为测试目标。多个候选无法区分时，继续独立检查，仍无法确定再询问。
5. 后续 ADB 操作始终显式传 `-s <实际设备序号>`，scrcpy 也指定 `--serial`。不把历史 `emulator-5556`、Niri 窗口 ID 或某个 AVD 名称当作常量。

本机已知路径与逐项命令见 [操作示例](references/commands.md)。它们是发现线索，不是跨项目固定配置。

## 启动与就绪

- 用户要求使用模拟器、当前没有适合实例时，启动现有合适 AVD。仅查看状态时不启动。缺少合适 AVD、SDK 或系统镜像时，说明缺失项；新建配置、安装软件或下载大镜像应在当前请求授权的范围内进行，不顺带改动项目。
- 本机常用“无自带窗口的模拟器 + scrcpy”方式；用户要自带窗口时不加 `-no-window`。`-no-snapshot` 是需要完整启动时的选择，不是所有问题的必选修复参数，也不等于清空数据。
- 优先复用已稳定运行的图形配置。本机 Emulator 37.1.11（build 15917651）运行 DSHX/API 36 时已报告 SwiftShader GLES 崩溃；需要重新启动这套环境时优先 `-gpu swangle`。不要在 `swiftshader`、`swiftshader_indirect`、`software` 之间循环尝试，它们在本次故障中共用出错路径。版本、应用或环境变化时重新核对帮助和实测结果，详见[本机渲染故障记录](references/commands.md#本机渲染故障记录)。
- 用工具提供的后台进程会话启动，保留会话标识和本次日志路径。不要为腾出端口关闭其他模拟器，也不要因锁文件存在就删除它。
- 启动后重新发现设备序号，核对 AVD 名称，再检查 `sys.boot_completed`。ADB 连接成功不等于系统启动完成，系统就绪也不等于应用或引擎就绪。
- 默认在约 120 秒内有界检查，每次命令或等待保持短时，持续工作时在 60 秒内更新进展。冷启动或低性能机器确需延长时，根据日志说明原因；不自动反复重启。

## 安装、显示与操作

- 当前任务已授权构建时才构建，按仓库约束执行当前模块检查；只请求打开模拟器时不构建 APK、不修改源码。
- 安装前核对 APK 实际架构、包名和目标设备。`adb -s <serial> install -r <apk>` 用于保留数据的覆盖安装；签名不匹配或版本降级时，报告原因，不自动卸载、清数据或放宽安装限制。
- 启动应用使用已核实的启动 Activity；Activity 是应用声明的页面入口，由项目清单或安装包提供。不要凭包名猜类名。安装成功、页面打开、服务运行与真实功能通过分别验证。
- 需要本机操作窗口时启动 scrcpy，标题包含任务/应用与实际设备序号。先确认没有属于该任务的可用镜像窗口，避免重复打开。
- 只观察时使用 `--no-control`；默认关闭音频和剪贴板自动同步，避免测试设备与桌面互相覆盖剪贴板。先用本机 `scrcpy --help` 核实参数。
- 自动点击前读取当前界面结构：用 UI Automator（Android 的界面测试工具）导出控件文字、可访问名称和坐标，再点击实际目标。不要复用旧截图坐标，窗口像素不等于设备像素；避免输出含敏感信息的整个界面树。
- 启动 scrcpy 会向设备临时推送它的显示服务；“只读镜像”只表示禁用输入控制，不代表设备零写入。

## 界面检查与证据

- **本机 Niri 桌面截图必须使用 [niri-window-screenshot](../niri-window-screenshot/SKILL.md)。** 先读取该技能，按实时窗口列表识别当前任务的 scrcpy 或模拟器窗口，再按窗口 ID 截图并打开检查。
- 不用 `adb screencap`、Playwright 截图或整屏截图代替用户规定的窗口截图。Niri 不可用时明确报告截图受限，不偷偷切换方案。
- 如需截图但窗口未打开，可在当前任务已授权运行/显示模拟器时先打开镜像，再调用截图技能；只有截图请求且目标不明时，按截图技能的目标识别规则处理。
- 图片可能在命令返回后才写入，按截图技能进行短暂、有界等待并验证能解码。截图成功不代表服务、网络或模型调用成功。
- 用量、模型响应、服务状态、会话保存等只根据对应验证结果报告。模拟器证据不写成 ARM 真机、16KB 页设备或真实服务商调用通过。
- 日志与网页调试可能含认证 URL、token、API 密钥和对话。优先按包名/进程和时间过滤，先脱敏再展示或截屏；完整敏感日志不进入源码仓库或技能示例。

## 故障与收尾

- `offline`、AVD 占用、黑屏、架构不匹配、网页组件太旧分别诊断，不使用统一“清空重装”。不要默认 `adb kill-server`、全局杀进程、删除 AVD 锁、`-wipe-data` 或卸载应用，这会影响其他任务或数据。
- 若模拟器进程的渲染线程以 SIGSEGV（非法内存访问）退出，先区分模拟器渲染器故障和应用崩溃。命中本机已记录的 SwiftShader 故障特征时，沿用 `swangle` 绕过方案，不仅凭内存紧张就判定 OOM（内存不足导致系统终止进程），也不盲目重建 AVD 或修改驱动。短时未复现仅作为阶段证据，不称根治或长期稳定；系统 core（崩溃时的进程内存转储）不自动删除或上传。
- 调试应用无需将未导出的服务改为对外开放，也无需默认开启 root、授予全部权限或修改系统安全设置。
- 用户要求停止模拟器时，重新核对设备序号和 AVD 名称，再对该设备执行 `adb -s <serial> emu kill`。只关闭镜像就结束该 scrcpy 会话。不要误杀其他项目的 Node、ADB 或虚拟设备。
- 创建本次临时 ADB 端口转发时记录映射，结束调试只移除自己创建的映射，不使用全局清除。复用用户或其他任务的设备、窗口、服务时不擅自清理。
- 最终说明所用 AVD、实际设备序号、Android 版本/架构、窗口情况、APK 安装与功能验证结果及未验证范围；是否保持运行按用户要求执行。只报告完成的步骤，不把打开模拟器包装为应用验收完成。
