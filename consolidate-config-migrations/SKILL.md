# 配置迁移收敛与指纹登记

只处理用户指定的配置及其迁移、默认值指纹和相关测试。遵守仓库 `AGENTS.md`；用户仅要求分析或生成 skill 时不修改项目源码。不要暂存、提交、还原已有改动。

## 确定边界

1. 用 `git status --short`、`git diff HEAD -- <相关路径>`、`git ls-files --others --exclude-standard` 查看暂存、未暂存和未跟踪改动；用 `git show HEAD:<迁移文件>` 确认最后一个已提交 schema 版本及其迁移链。读取当前配置类型、默认值、指纹实现与现有测试，不以单次 `git diff` 代替完整检查。
2. 核实待收敛的版本均晚于已提交版本，且确实未进入发布或持久化配置。**未提交不等于未部署**：如果已有用户或测试环境写入过这些中间版本，收敛会使新代码把它们判为未来版本；先说明兼容风险并取得处理方式，不擅自删除升级路径。
3. 确定最终版应保留的字段、默认值、数据转换及管理员自定义值。区分“已提交版本的真实旧数据”与“未提交中间版本才出现的旧默认值”；后者的专用升级步骤通常不应进入合并后的迁移。

## 收敛迁移

- 以最后已提交版本 `V` 为起点，仅登记 `V→V+1` 一段，删除这次未提交改动引入的其余登记与孤立迁移函数；不改动 `V` 以前的历史链。若用户指定的范围中还有其他配置，分别判断，不混用版本。
- 将确有必要的字段转换合到这一段；缺失值若由迁移引擎合并当前默认值，就不重复手工赋值。保留已有自定义值，谨慎处理字段缺失、显式空值和旧字段删除。根据最终版语义处理临时默认值转换，不为了保持不存在的过渡版本而保留无效逻辑。
- 在**已有测试文件**中调整过渡版本用例为 `V→V+1`：覆盖旧配置缺失新字段、已有自定义值、废弃字段、最终落盘与重新加载；删除只针对未发布中间版本的断言。不为一两个测试新建测试文件。

## 登记指纹并验收

- 先确认最终配置模型和默认值，再用仓库自身的默认值指纹函数计算最终摘要。这个仓库可通过 `pkg/config/migrate.DefaultsFingerprint` 或配置包的指纹测试取得 `actual`；其计算包含 `schema_version`，收敛版本后旧哈希通常失效。核对规范化随机实例字段的规则，**只在确认最终默认值符合预期后**人工写入 `expected`，同步更新版本说明。不要通过关闭校验、硬编码测试期望或运行时自动接受新指纹来消除报错。
- 仅运行相关配置包的测试（如 `go test ./cmd/server/appconfig`），并检查 `gofmt -d`、`git diff --check` 和迁移链中有无残留版本引用；不要运行全量测试。测试失败时查明原因再修改，并重跑同包测试。
- 报告旧版到新版的对应关系、被移除的过渡逻辑、登记的新指纹及测试结果；对已持久化中间版本的兼容风险如实说明。
