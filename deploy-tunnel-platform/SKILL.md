# 穿透平台部署

默认执行快速部署。首先发现连接阻塞，认证与构建并行；不要让用户等到打包完成才得知 SSH 无法登录。

## 第一轮就处理 SSH，同时准备产物

1. 从当前会话确定目标和已有凭据。filesharing.asia 的位置与命令见 [references/filesharing-asia.md](references/filesharing-asia.md)。用户已提供目标密码时直接使用，不再索要。
2. 第一轮工具调用就探测 SSH：优先复用控制连接或已知密钥，使用 `BatchMode=yes`、`ConnectTimeout=5`、`ConnectionAttempts=1`，整个探测用 `timeout 10` 限时。不要逐个穷举密钥、SSH agent 或遍历历史日志查找密码。已有密码时可直接认证，无需先重试已知失败的密钥。
3. 没有可用凭据，或本次认证被拒绝且没有其他已知有效方式时，**立即调用 `functions.request_user_input_async` 弹窗**，不能只在最终回复里要求密码。问题注明目标，例如：“请提供 root@47.106.74.102 的 SSH 密码，仅用于本次部署；前后端正在后台打包。也可以提供已授权私钥或控制连接路径。”使用自由文本输入，不设置密码选项。该工具是普通文本问答，不宣称输入被遮蔽或不会进入会话记录；有专用密码输入能力时优先使用。若工具不可用，立即在回复中请求凭据，不等待构建结束。
4. 弹窗发出后继续独立工作：阅读适用仓库指令，核对分支与工作区状态，复用现有发布包或启动前后端构建。后端与前端用独立进程并行执行；前端构建、字体复制、打包有依赖，按顺序执行。不要在读取 SSH 结果前阻塞等待构建，也不要阻塞等待用户填密码。
5. 用户回复后立即认证并复用 SSH 控制连接，不重新构建已完成的产物。凭据待回复期间保持问题有效；等待超时不等于取得凭据。认证失败及时回报，不对同一凭据反复尝试。主机密钥变化和网络不可达应报告实际原因，不伪装成缺密码。

密码只用于认证，不回显、不写入 skill、脚本、环境配置或报告；用内存/标准输入/文件描述符交给认证程序，避免命令行参数泄漏。SSH 成功后用一次远端命令批量核对架构、服务实际路径、数据目录和剩余空间。

## 最少必要的构建

- 用户说“当前前后端”时包含当前有效的未提交源码；不切换分支、不提交或回滚工作区，不顺带修业务代码。
- 用户或前一轮已经准备好发布包时，先读该包的构建结果、来源和时间。已确认构建后没有相关源码变化，就直接上传；不要因为 SSH 失败重新跑构建、测试或打包。来源不明或相关源码已经变化时只重建受影响部分。HEAD 相同不代表未提交源码相同。
- **默认不生成或逐项校验源码/产物 SHA-256 清单，不下载线上大脚本做哈希比对。** 只检查构建、传输、解压退出状态，后端可执行权限及 Web 必需文件存在。仅用户明确要求，或确实遇到传输损坏/产物错配时增加针对性校验。
- **单纯部署默认不重跑 Go/Flutter 测试、不跑静态审查、不重做源码审计。** 复用已完成的检查，报告未运行项；本次确实改过源码、仓库明确要求或用户要求验收时，才执行受影响包的必要检查，禁止默认全仓测试。已有无关失败记录一次，不重复排查来拖延发布；构建、目标协议或配置迁移的阻断问题不能忽略。
- 后端与前端编译并行，保留增量缓存，不执行 `go clean`、`flutter clean` 或无关依赖升级。Web 使用实际 `lib/web_main.dart` 入口、`/web/` 基路径，保留字体复制。
- 仅需上传目录时直接构建 Web 并复制字体，避免先生成 ZIP 再重复压缩成 tar.gz。需要压缩传输时优先一次低压缩级别打包，例如 `tar -I 'gzip -1'`。
- 在仓库外保留构建日志、产物及简短发布结果即可，不要求大规模文件清单和长篇审计报告。

## 发布和回滚

- 明确的部署请求已授权目标内的上传、替换、重启，不再请求确认。
- 产物准备好且 SSH 成功后立即上传到 Web 根目录之外的独立发布目录。上传、解压成功且必需文件完整后才停止旧服务。
- 保留旧后端和 Web 目录，并备份配置、身份、服务单元及数据库。同一文件系统优先重命名保留旧产物，避免重复压缩。备份目录仅运维账号可读，不放进公开站点。
- SQLite 用在线备份 API，或停止并确认进程退出后复制一致的数据库及必要旁文件；不能只复制运行中的 `.db`。默认不打包无关缓存、旧日志、下载文件和历史发布。
- 整目录切换 Web，替换后端，使用现有 systemd 服务启动。保留原有配置与历史用量，不自动改端口、安装 helper、清数据库或重置账号。
- 按已知启动时长设定有限健康检查窗口。filesharing.asia 曾有 120 秒 AI helper 等待，适用时给 180 秒上限；服务一旦就绪立即结束等待，不固定睡满。单次工具等待最多 60 秒，保持进度更新。
- 启动失败恢复旧前后端并检查旧服务恢复；保留失败日志，停止盲目重复切换。发生配置/数据库迁移时先确认旧版本可恢复，不能自动回放旧数据库覆盖新用量。

## 默认上线检查

只做以下短检查，能合并的请求合并执行：

1. systemd active，进程启动时间属于本次切换，可执行文件路径正确，未出现重启循环。
2. `/web/` 与平台发现接口可访问，HTTPS 正常校验证书；不下载整套前端重复校验。
3. HTTPS 与 TURN TCP/UDP 监听存在，近期启动日志没有目标服务致命错误。

检查通过就报告上线完成。默认不启动浏览器操作、统计 API 登录、数据库全表对账、TURN 流量探测、虚拟机或压力测试；这些仅在用户另行要求验收或定位故障时执行。基础上线检查不等于真实 NAS P2P/文件传输已验证。

## 交付

简短报告访问入口、是否已切换、服务状态、备份位置，以及影响使用的已知问题。不要用哈希表、测试列表或长报告替代完成部署。若 SSH 阻塞，用户应早已收到弹窗；产物准备好后继续等所需凭据，收到后接着上传。完成后关闭本次临时 SSH 控制连接，保留备份。
