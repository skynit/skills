# niri 窗口截图

调用 niri 自带的 `screenshot-window --id`，将指定窗口保存为 PNG，再读取图片完成界面检查。默认保持窗口焦点、尺寸、位置和工作区不变。

窗口 ID 是 niri 为窗口分配的数字，用来指定截图目标；应用标识 `app_id` 表示窗口所属的应用，窗口标题 `title` 表示该窗口当前名称。同一个应用可以有多个窗口，因此不能只凭应用标识就选择列表中的第一个窗口。

## 确认本机支持

读取实际运行版本及命令帮助，不根据版本号猜测参数：

```bash
niri msg version
niri msg action screenshot-window --help
```

确认帮助包含 `--id` 和 `--path`。缺少参数或无法连接当前 niri 会话时，说明具体错误并结束本次截图；不要自动切换成调整窗口后截全屏，也不要为了截图修改 niri 配置或安装软件。

## 选择目标窗口

```bash
niri msg --json windows
```

从实时返回的 `id`、`app_id`、`title` 等字段识别用户指定的窗口。窗口 ID 每次从运行中的 niri 获取，不把上次使用的 ID 当成稳定配置。

- 用户已提供窗口 ID 时，确认它仍在列表中，且与本次目标一致。
- 同一应用存在多个窗口时，结合标题和当前任务判断；证据不足才请用户指定窗口。
- 仅在用户明确要求“当前窗口”时，使用 `niri msg --json focused-window` 确认目标。
- 目标没有打开时报告未找到；不擅自启动应用。

## 保存窗口截图

使用当前任务的输出目录及唯一文件名；用户提供保存路径时按其要求处理。路径必须是绝对路径，包含空格时正确引用。不覆盖已有图片，除非任务明确要求覆盖。

以下命令仅展示参数形式，执行前将 `123` 换成刚确认的真实窗口 ID，将路径换成此次输出位置：

```bash
niri msg action screenshot-window \
  --id 123 \
  --path /tmp/niri-window-capture/window.png \
  --show-pointer false
```

执行前创建必要的输出目录。始终明确传入 `--id`，防止焦点变化导致截错窗口。默认不包含指针；用户要求显示指针时使用 `--show-pointer true`，并说明 niri 仅在目标窗口正接收指针输入时包含指针，不为此移动鼠标。

**剪贴板副作用：** 当前本机 niri 的命令帮助说明，截图除保存到磁盘外也会写入剪贴板；`--write-to-disk false` 只会禁止磁盘保存，不会禁止剪贴板写入。首次使用时简短说明，无需因该已知行为重复索取截图许可。若用户明确要求保留剪贴板，先确认本机是否有支持该要求的接口；没有时说明限制并停止，不承诺剪贴板不变，也不读取、备份或恢复其原内容。

## 验证和展示

命令成功返回不等于图片已可读取。先确认本次生成的文件存在、非空、能够解码，并检查图片尺寸。若文件仍在写入，进行短暂、有界的等待和读取重试，累计不超过 5 秒；不要无限轮询。

使用可用的本地图片查看工具打开 PNG，例如 `view_image`，核实目标窗口和用户要检查的界面内容。无法打开图片时如实报告，不凭命令退出码宣称已完成视觉检查。

按窗口当前实际尺寸截图，不为获得某个分辨率而擅自调整窗口。不要承诺离屏、其他工作区或被遮挡窗口一定包含最新帧；以实际图片为准。图片为空白、陈旧或内容不符时说明观察结果，不通过切焦点、移动窗口或全屏化来自动修正。

窗口在截图前关闭而导致 ID 失效时，可重新查询窗口列表，仅在能确认是同一目标重新打开的窗口时重试一次；仍失败则报告错误。

向用户展示截图时使用绝对路径：

```markdown
![目标窗口截图](/absolute/path/window.png)
```

回复包含实际文件位置和与任务有关的观察；需要区分“截图成功”与“图片证明了什么”。截图本身不代表应用功能、接口或交互已经通过测试。
