# 实施与验收

目标是以最小结构改动完成视觉换肤。功能、字段、路由、权限、数据和行为保持原样。

## 先识别目标技术栈

从 `package.json`、lockfile、入口文件和现有目录判断：

- React / Next.js：优先复用现有组件、样式方案、主题和图标库。
- Vue / Nuxt：复用 Vue 组件与项目主题；不要引入 React 组件。
- 原生 HTML/CSS：使用 `assets/qoder-ui.css` 的视觉原语，再映射到真实类名。
- Tauri / Electron：只改 Web 渲染层外观；原生窗口行为保持不变。

框架不是视觉风格的前提。不要因为本 skill 提到 React 或 Tailwind 就新增依赖。

## 不改变产品设计

改造前先列出：

- 当前页面和组件的职责。
- 不能改变的信息层级。
- 不能增删的业务入口和字段。
- 当前主题、图标和组件库。
- 受影响的 package 与最小验证命令。

如果视觉调整必须改动 DOM，只允许做语义等价调整，例如补 wrapper、稳定布局列、增加可访问名称。不得顺手改业务流程或数据。

## 不臆造私有设计系统

如果资料提到 `@design-llm/qoder-design`，只有目标项目已经声明依赖、lockfile 可解析且实际可导入时才可使用。否则：

- 不写不存在的 import。
- 不猜测组件 props。
- 不声称已经接入 Qoder 官方设计系统。
- 用语义令牌和现有组件样式实现视觉效果。

## 令牌架构

至少定义以下语义令牌：

```css
:root {
  --q-background: ...;
  --q-surface: ...;
  --q-surface-elevated: ...;
  --q-surface-muted: ...;
  --q-border: ...;
  --q-border-subtle: ...;
  --q-text: ...;
  --q-text-muted: ...;
  --q-text-faint: ...;
  --q-primary: ...;
  --q-focus: ...;
  --q-success: ...;
  --q-warning: ...;
  --q-danger: ...;
}
```

要求：

1. 业务组件只使用语义令牌。
2. 颜色先按用途命名，再赋值；不要把 `gray-2` 直接写进按钮。
3. 默认主题保持中性，暗色主题替换同一组语义令牌。
4. 密度和形状通过独立变量控制，不复制整套颜色。
5. Tailwind 可使用 `bg-[var(--q-surface)]` 等映射，不在原子类中散落相近 HEX。

`assets/qoder-ui.css` 使用 `q-` 前缀，复制后应按项目命名习惯改名，避免污染全局样式。

## 替换顺序

1. 引入或合并语义令牌。
2. 调整全局字体、背景、文字、边框和 focus ring。
3. 统一现有基础控件：Button、IconButton、Input、Select、Switch、Tag。
4. 统一复合组件：列表行、工具条、表头、分组面板和浮层。
5. 处理项目已有特殊区域，例如侧栏、工具栏、编辑器或内容列。
6. 检查长文本、固定宽控件和窄视口。

不要从一个页面开始复制一整套硬编码颜色。优先改共享层，减少例外。

## 主题与风格属性

需要明暗主题时，在根元素设置：

```html
<html data-theme="light" data-style="neutral">
```

约束：

- `data-theme` 只控制颜色。
- `data-style` 只控制密度、圆角和间距。
- 不通过 CSS invert、整页滤镜或色相旋转实现暗色模式。
- 暗色主题保持与浅色主题相同的层级关系。
- 如果项目已有主题机制，接入现有机制，不另建第二套切换逻辑。

按需实现风格值，不要求一次支持全部：

- `neutral`：默认 8px 圆角和中等密度。
- `compact`：更小行高和 6px 左右圆角。
- `soft`：更宽松的间距和 10px 左右圆角。
- `sharp`：2–4px 圆角。
- `dense`：表格、日志和高密度数据的紧凑尺寸。

## 样式实施

- 用 Grid 稳定左侧图标列、主内容列和右侧控件列。
- 主内容列使用 `minmax(0, 1fr)` 和 `min-width: 0`。
- 固定格式元素设置稳定高度、最小宽度或 `aspect-ratio`。
- 长文本按原有语义选择换行或 ellipsis；ellipsis 时提供 title 或详情入口。
- 全局 focus ring 使用 `--q-focus`，确保不被 overflow 裁切。
- 只对颜色、边框、透明度和少量 transform 做动画。
- `prefers-reduced-motion` 下移除非必要动效。

## 可访问性外观

- 正文与背景保持可读对比度；muted 文字不能用于关键状态。
- focus-visible 始终可见，且与 hover/selected 区分。
- 禁用态文字仍可辨认，不把整个控件透明度降到不可读。
- 危险色不是唯一信号，保留图标或明确文字。
- 状态不只靠颜色表达。
- 字号放大到 200% 时控件文字不重叠，主要布局仍可使用。
- 图标按钮保留可访问名称；视觉换肤不能移除原有 `aria-label`。

## 预览与实施门禁

目标仓库或用户要求 Preview-first 时：

1. 先生成 `1440x900` 视觉预览。
2. 必要时补 `960x640` 窄桌面预览。
3. 预览只改变视觉，不增加假业务数据。
4. 向用户展示并取得明确批准。
5. 批准后再写目标界面的 Vue/CSS/React。

只改 token、字体、局部颜色或无视觉行为的 bug 时，可按项目规范跳过预览，但不得扩大范围。

## 验证

只执行受影响 package 的最小检查。使用项目实际脚本，不照抄命令。禁止全仓测试、`pnpm -r` 和无关构建。

代码层重点：

- 类型检查通过。
- 现有组件测试通过。
- 原有点击、键盘和状态行为没有被视觉改造破坏。
- 新增全局样式没有明显选择器污染。

视觉层重点：

- `1440x900`、目标常见窗口和 `960x640`。
- 浅色、暗色及项目实际使用的密度风格。
- default、hover、selected、focus-visible、disabled、danger。
- 长标题、长路径、长按钮文字和空内容。
- 页面级不出现横向滚动、控件重叠或固定区域跳动。

Web 页面可用 Playwright 截图。本机桌面窗口使用窗口级截图，不切换焦点、不截整屏。截图后实际检查交互状态，不只看静态首屏。

## 交付说明

只报告亲自验证过的事实：

- 视觉令牌和主题如何变化。
- 哪些共享组件或页面外观被更新。
- 原有功能、信息架构和流程未改动的证据。
- 执行了哪些 package 内检查。
- 哪些视觉状态或视口已验证，哪些未覆盖。
