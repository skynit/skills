# CWNAS 真机部署验收

先确认目标与功能配置，完成本地构建和定向检查，再部署并验证本次涉及的 API。此技能不把验收请求自动扩展为源码修复、全量测试或完整 AI 验收。

## 1. 发现仓库、执行环境和目标

- 从当前会话、工作目录和 `git rev-parse --show-toplevel` 定位目标 CW 仓库，以 `go.mod` 中的模块及 `cmd/server` 入口核实，不使用历史开发机的绝对路径。以下源码路径均相对本次仓库。
- 读取根及相关目录的 `AGENTS.md`；主服务构建读 `cmd/server/AGENTS.md`，AI 或 helper 变更按 `pkg/ai/AGENTS.md` 的指针读取实际相关指南。构建方法以当前 `README.md`、`go.mod`、构建标签及现有脚本为准。
- 识别本机操作系统、shell、Go/C 工具链和已有 Linux 构建容器。原生 Linux 在已满足目标依赖时构建；Windows、macOS 或宿主 ABI 不兼容时复用项目已有 Linux 构建环境，路径挂载及引用按实际 shell 生成，不把 PowerShell 命令用于 POSIX shell。
- 无其他指定时可沿用测试目标 `root@192.168.100.247`、HTTPS 端口 `9081`、远端暂存/安装目录 `/home/cwnas/9081`；执行前复核主机身份、架构、实际服务路径和本次授权，用户指定值优先。先按目标架构选择产物，不凭宿主架构推断。
- 检查分支、完整工作区状态和相关改动，保留已有修改；本任务仅处理技能时，到本地文件验证结束，不连接目标机。

## 2. 确定构建标签与产物

先区分本次改动与目标已经启用的功能。目标已有的 `localai`、`webai`、`intel` 等标签按当前注册代码、构建记录和部署配置核实并保留；不能因为本次只改普通接口，就构建缺失原有能力的版本。无法确认且会改变目标能力时先澄清。

- 主程序入口为 `./cmd/server`，按目标平台、架构和标签构建。输出放当前仓库约定的产物目录或本轮临时目录，记录绝对路径；不依赖已移除的其他编译技能。
- 本地推理使用 `localai` 时，按当前仓库要求启用 cgo 并准备 C 工具链及相关依赖；云端 AI 或普通业务变更不自动要求新增本地推理能力。
- LanceDB helper 是独立进程，入口为 `./cmd/lancedb-helper`。本次修改 helper、主辅进程协议、原生依赖或运行库发布契约，且验收需要新 helper 时一并构建；其余情况核实并复用目标上兼容的 helper，不因任意 AI 目录改动就重建它。
- 主程序不链接 LanceDB 静态库；helper 才需要与当前依赖配套的目标平台原生库及 cgo 配置。先检查 `pkg/ai/vectordb/lancedb/cgo_flags_*` 和当前构建说明要求的文件，不把“主程序可构建”当成 helper 可构建，也不以缺库为理由移除目标原有功能。
- Linux helper 使用当前仓库要求的兼容构建环境；当前 README 指定 Bookworm 工具链。从 `go.mod` 和现有环境确定 Go 版本，并检查实际产物的 GLIBC 要求，避免把宿主的新系统依赖带到旧 NAS。

当前主程序构建形式如下：`cwnas_accept_output` 须先设为本轮已确认的绝对产物路径，实际标签和目标环境按上述核实结果补齐；只有本机工具链能生成兼容的 Linux 产物时才直接执行：

```sh
go build -buildvcs=false -trimpath -ldflags='-s -w' -o "$cwnas_accept_output" ./cmd/server
```

只运行本次实际涉及包内的最小必要检查，定向用例运行后确认命中；不运行全仓测试。构建或必要依赖检查失败时停止部署。记录产物路径、大小、SHA-256、目标格式和使用的标签；AI 编译不代表真实模型能力已验证。

## 3. SSH 连接与公钥授权

优先复用当前会话已有的控制连接、SSH 配置、agent 或已知密钥。用有界的 `BatchMode` 探测连接，区分网络不可达、主机密钥变化和认证拒绝；不遍历历史日志寻找密码。

需要公钥时，从当前用户的 SSH 配置和实际用户目录发现密钥，不固定旧 Windows 用户目录或密钥类型。保留已有私钥；有私钥但缺公钥时可在已授权范围内导出公钥，不能覆盖或重新生成原密钥。

生成密钥或追加远端 `authorized_keys` 前，检查用户是否已经授权该操作；未授权时说明目标和影响后确认一次。密码需要时优先通过本地终端安全输入，不要求用户把密码粘贴到普通聊天中。授权完成后再次验证免密连接，仍失败则报告实际原因并停止。

## 4. 暂存、部署与恢复

1. 核对目标为预期 Linux 设备，检查架构、磁盘空间和服务执行路径，记录部署前服务及重启计数；已有安装位置从目标服务定义及项目安装实现确认，不以工作目录猜测。
2. 将产物上传为本轮唯一的临时文件，对比本地和远端 SHA-256，检查目标可执行格式。替换前保存现有二进制，以及本轮实际会改动的配置或服务文件。
3. 复用项目当前安装/更新入口。若目标确实使用 `/home/cwnas/9081` 的独立安装方式，在该目录完成同文件系统重命名、执行权限设置及 `./cwnas install`；已有其他布局时沿用其实际入口，不强行切换目录或重装系统服务。
4. 需要更新 helper 时，按运行时解析出的实际位置部署 `cwnas-lancedb-helper`；从当前 `pkg/ai/vectordb/lancedb/remote/helper.go` 核对位置规则。涉及主辅协议同时变化时协调停启和替换，确认旧 helper 已退出、新进程运行的是本轮产物，不能仅复制文件就宣称更新完成。
5. 启动失败时采集相关服务和进程日志，按本轮备份恢复旧产物并验证旧服务恢复；存在配置或数据迁移时先核实回退兼容性，不直接用旧数据库覆盖新数据。

## 5. 验证本次 API 并报告

- 检查主程序和需更新 helper 的正式文件校验和、实际运行路径、服务状态及监听端口。比较部署前后的异常重启记录并观察服务稳定性，不要求历史重启计数必须为零。
- 沿本次代码差异和实际注册点找受影响 API，验证成功路径、关键字段、相关失败分支及日志。只修改非 AI 功能时不扩展为模型安装、批量图片导入或整套 AI 搜索验收。
- 涉及本地推理、向量库或 helper 时，另验对应运行时健康及本次能力，区分编译通过、服务可用和模型行为已验证。
- 鉴权信息仅供本轮调用，不输出完整 Token、密码或 Cookie；除 HTTP 状态外检查业务状态。完整 AI 验收仅在用户明确要求时执行。
- 验收发现代码问题时报告证据和修复建议；已有明确修复授权才进入最小修复、定向验证、重建和再次部署，不因验收失败自动扩大源码修改范围。

交付目标机、目录、分支或提交、构建标签、产物 SHA-256、备份位置、服务状态和实际验证的 API。明确未验证的平台、原生依赖、真实模型和未解决问题。
