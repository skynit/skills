# 编写 DMS 插件

## 先确认边界

- DMS 是加载插件的桌面外壳；Quickshell 是它使用的 QML 运行框架；QML 是插件界面语言。`plugin.json` 是 DMS 读取的插件清单，声明入口、能力、权限和运行依赖。后台辅助程序只承担 QML 不适合处理的工作，不能代替 QML 插件界面。向用户解释这些概念时，首次出现就说明各自职责。
- 先读目标仓库的 `AGENTS.md`、现有插件、已安装 DMS 版本和实际支持的接口。可用 `dms version`、`dms ipc --help`，并查看当前版本的本地范例或上游文档。不要把旧会话中的清单字段、QML API、DMS 版本和安装路径视为永久契约。
- 在本机没有另行指定源码仓库时，先查看 `~/workspace/dms-plugins/`。每个插件是独立目录，顶层放 `plugin.json`；已安装副本通常位于 `${XDG_CONFIG_HOME:-$HOME/.config}/DankMaterialShell/plugins/<目录名>/`。目录名和清单 `id` 可能不同，调用 IPC 时使用 `id`。安装副本不是唯一源码。
- 明确用户需要的数据来源、运行平台、展示位置、是否离线、持久化内容、权限和外部程序。缺少关键产品选择时再询问；其余按现有插件和用户指令决定。遵守目标仓库的设计预览门禁、修改授权和测试范围。

## 实现

1. 选取最接近的现有插件核对 `PluginComponent`、状态栏组件、弹窗、设置组件、主题变量和键盘交互。只写当前需求用到的文件与 `plugin.json` 字段。插件界面使用 DMS 主题与组件；状态来自真实服务或辅助程序，缺失时展示可理解的空态或错误，不伪造数据。
2. `permissions` 只声明实际使用的能力，`dependencies` 或当前 DMS 版本采用的等价字段只列运行机器需要的命令。构建工具与运行依赖分开说明；例如词典构建脚本不等于查询插件的运行时依赖。新增进程调用时传参数数组，不把用户输入拼进 shell 命令。按需要校验输入、限制文件访问范围，并避免把配对码等秘密写入命令行或持久配置。
3. 简单取数先检查 DMS/Quickshell 已提供的服务或 QML 能力；复杂协议、数据库、进程编排需要辅助程序时优先用 Go，不新增 Python 运行时依赖，除非有明确的技术理由或用户另行指定。已有 Python 构建工具可留在构建侧，但不要因此要求目标机器安装 Python。Go 辅助程序尽量以 `CGO_ENABLED=0` 构建；面向通用 x86-64 机器时，在构建脚本和 README 手动构建命令中显式使用 `GOAMD64=v1`，确保外部环境设为 `v4` 时产物仍为 `v1`。其他架构按其实际 `GOARCH` 构建，不把 `GOAMD64` 当作通用架构选项。禁用 cgo 不会消除被程序调用的 `adb`、`scrcpy`、`ffprobe` 等外部工具。辅助程序与 QML 之间定义稳定的 JSON 输入、输出和错误形状。
4. 设置由插件自己的 UI 或 DMS 设置组件管理，先查现有持久化接口。状态栏入口、弹窗和设置应可用键盘操作，有可读名称与状态文字；长内容、缩放和窄栏位不能溢出。对多个候选对象、缺失权限、命令失败及无数据分别给出真实结果，不把“已保存”误作“已连接”。
5. 若用户要求发布或本机生效，只复制运行必需的文件到该插件的安装目录；复制前核对安装副本的现有修改，不覆盖用户另行改过的内容。首次扫描用 `dms ipc call plugin-scan scan`；定向重扫或重载时带插件 `id`，如 `dms ipc call plugin-scan rescan <id>`。用 `dms ipc call plugins list` 或 `plugin-scan status <id>` 检查发现和加载；启用及状态栏放置是两个独立步骤。不要用可能访问在线仓库的 `dms plugins install/list` 代替本地文件安装。DMS 未运行时先确认用户会话状态；仅在引用的 QML 缓存确实未更新时考虑重启 DMS。

## 验证与交付

- 只运行当前插件目录内最小的逻辑测试、清单解析和受影响 QML 文件检查；按仓库规定在已有测试文件中增加测试，避免为一两个断言新建测试文件。`qmllint` 缺少 DMS 私有 `qs.*` 导入或无法解析现有语法时，记录具体限制，并以 DMS 实际加载日志和界面行为补验，不把无诊断退出码当作全部通过。
- 涉及后台辅助程序时，核对真实 JSON 契约、错误路径和运行依赖；迁移旧实现时，先用同一输入对照结果，再切换 QML 调用入口。对带构建脚本的 x86-64 Go 程序，可在外部设 `GOAMD64=v4` 执行当前插件的构建脚本，再用 `go version -m` 确认产物仍为 `GOAMD64=v1`，并核对 `CGO_ENABLED`；只验证当前插件，不触发其他包的构建。涉及真实设备、网络或录制时，明确区分模拟测试与实际验收。
- 安装后检查插件已加载、入口是否放置并可见、弹窗或设置是否可操作，以及 `journalctl --user -u dms.service` 中的相关错误。只报告亲自验证过的事实和未验证的环节；附源码位置、安装位置、运行依赖、用户下一步操作。

## 本机可参考的实现

在 `~/workspace/dms-plugins/` 存在时，按任务选择范例：`LocalStatus` 展示复用 DMS 服务、状态采样和设置；`LocalTranslate` 展示离线词典与 JSON 辅助程序；`LocalLyrics` 展示播放器状态和外部工具；`PhoneConnect` 展示进程编排、用户输入及设备状态。它们提供结构范例，不保证版本、依赖清单和实现语言始终最新。桌面专属的配置管理与 IPC 注意事项另见 `~/.codex/skills/cachyos/dms.md`；该文件不替代当前 DMS 的实际接口检查。
