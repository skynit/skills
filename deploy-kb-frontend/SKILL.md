# 部署知识库前端

## 默认目标

以下是 2026-09-15 已验证的部署配置，执行前复核；用户本次指定的路径、服务器和域名优先。

| 项目 | 默认值 |
| --- | --- |
| 前端仓库 | `/home/skynit/workspace/cwnas_kb/frontend` |
| Git 远端 | `git@192.168.100.168:cwnas/knowledge_base_frontend.git` |
| 构建命令与产物 | `npm run build` → `dist/` |
| SSH 目标 | `root@139.196.42.76` |
| 部署根目录 | `/var/ai` |
| 当前站点目录 | `/var/ai/html` |
| 上一版目录 | `/var/ai/html2` |
| 验收地址 | `https://ai.cwnas.com` |
| Web 服务 | Nginx，站点 root 为 `/var/ai/html` |

此技能只处理前端产物。Git 合并、提交、推送及源码修改需要对应任务指令；不要把它们作为部署的前置动作。用户只要求打包时，交付压缩包即可。

## 构建与连接

1. 在实际前端仓库读取适用的 `AGENTS.md`、`package.json`、`git status --short --untracked-files=all`，记录当前提交及是否包含未提交改动。保留已有改动，用当前工作区构建。
2. 用户要求部署即已授权本次上传和目录切换，后续不重复询问确认。可并行执行本地构建和远端只读预检。缺少凭据时尽早收集，同时继续本地准备。
3. 优先复用可用 SSH 密钥或当前会话最新提供的凭据。密码通过不回显的 SSH 提示输入，不写入技能、脚本、命令行参数或日志。可用临时 `ControlMaster` socket 复用连接完成上传和校验，结束后关闭。认证失败后索取修正凭据，不循环重试；有明确的特殊字符转义歧义时，最多核对一次原始格式。
4. 执行用户要求的 **`npm run build`**，确认退出码为 0 且 `dist/index.html` 存在。构建失败则停止发布。只做当前前端包的相关检查，不运行全量测试；必要时使用生产预览检查受影响的页面。
5. 生成带提交号、时间戳的压缩包，保留顶层 `dist/`。默认使用系统 `tar` 创建 `.tar.gz`，无需为压缩安装依赖；用户指定 ZIP 时使用 ZIP。输出目录选临时目录或已有产物目录，避免引入无关未跟踪文件。
6. 记录压缩包 SHA-256，以及 `dist` 内每个文件相对路径、SHA-256 和总数。验证压缩包能读回相同内容。整个部署使用这一份构建产物。

## 远端准备

- 检查 `/var/ai`、`html`、`html2`、待解压路径的真实类型、空间和权限。查看 Nginx 当前配置中对应域名的 root，确认操作的是实际站点。若目录是符号链接、root 不符或存在未知部署布局，先厘清；不要套用目录移动命令。
- 上传压缩包到 `/var/ai/` 下唯一的文件名，比较远端与本地 SHA-256 后再解压。已有同名包只有校验一致才可复用，不一致则换名。
- 可解压至空闲的 `/var/ai/dist`；它已存在时使用本次唯一的暂存目录，保留原目录。解压时不继承本地用户身份。核对顶层 `dist/`、`index.html`、全部文件清单和校验值，确保 Nginx 用户可以读取文件、遍历目录。
- 核验完成前保持当前 `html` 不变。记录当前 `html` 和已有 `html2` 的身份或内容摘要，切换前再次比较，避免覆盖期间发生的其他发布。

## 目录切换

把下面的移动放在同一个远端操作中执行，使用同一文件系统内的目录重命名。每个目标路径必须空闲，避免 `mv` 把目录嵌套进已存在的同名目录。

1. 若已有 `html2`，先改名为唯一的 `html2.previous-YYYYMMDDTHHMMSSZ`，保留更早备份。
2. 将当前 `html` 改名为 `html2`。
3. 将已验证的暂存 `dist` 改名为 `html`。

为步骤 2、3 的失败准备回退：若旧 `html` 已移动而新目录尚未就位，将 `html2` 移回 `html`；恢复本次刚改名的更早备份到原位置。首次部署没有 `html` 时不虚构上一版备份。回退也不得覆盖其他操作新建或修改的路径。

静态目录切换通常不需要重启或修改 Nginx。保留压缩包和备份，不自动清理历史版本。

## 发布验证与交付

- 比较切换后的 `/var/ai/html` 与已验证的暂存产物，确认上一版确实位于 `html2`；检查 Web 服务状态。
- 通过目标域名和正确 TLS 主机名请求站点。需要绕过 DNS 或代理确认指定服务器时，使用 `curl --noproxy '*' --resolve ai.cwnas.com:443:139.196.42.76 https://ai.cwnas.com/...`，不要仅凭访问裸 IP 判断站点。
- 检查 `/`、`/help`、从本次 `index.html` 发现的入口 JS/CSS，以及存在时的 `WikiArticleView-*.js`、`WikiArticleView-*.css`。资源哈希文件名每次构建会变化，必须从实际产物发现。
- 同时核对 HTTP 成功状态和响应内容 SHA-256；SPA 回退页返回 200 不能证明某个 JS/CSS 文件可用。必要时在远端使用域名指向 `127.0.0.1` 的请求，区分本机服务与外部网络问题。
- 确认新版静态资源导致失败时，在路径未被其他操作改动的前提下，保留失败的新目录并恢复上一版 `html`。只做一次明确的回退；状态不明或回退失败时停止后续切换，报告实际路径。不要为修复网络或 TLS 问题擅改无关服务配置。
- 报告构建结果、远端压缩包路径、当前目录、上一版和更早备份路径、访问地址及验证结果。区分本地模拟数据浏览器检查、远端文件校验和真实 HTTPS 响应，不把静态部署成功表述为完整业务接口验收。
- 关闭本次 SSH 复用连接和临时预览进程，保留可供复查的非敏感构建校验记录。
